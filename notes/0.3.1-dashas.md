# Step 0.3.1 — Vimshottari dashas: report

PR #15, branch `0.3.1-dashas`. Engine version 0.2.0. All numbers below come from `node notes/0.3.1-dasha-report.ts` (read-only; re-run it to reproduce). Only the synthetic reference births were used.

## Summary

- The engine calculates the full Vimshottari timeline (9 mahadashas → 81 antardashas → 729 pratyantardashas) from the true start of the mahadasha running at birth, plus "current period" and "coming up" for a moment that is passed in. The chart API returns it as `dashas`.
- **JHora dasha tests: all on and passing**, tolerances unchanged: 2,349 antardasha start dates (29 births), 180 pratyantardasha start/end times (R01, R09, R10, R15, R22), plus structure checks for all 29 births.
- Differences from JHora come only from the known ≈0.14″ Lahiri offset (D-079) and the pre-1900 ΔT drift (D-081): each birth's dates are shifted by an almost constant amount (largest 30.7 min from 1900; 4.6 h for R26, 1853).
- **D-097:** JHora prints every dasha date on the **fixed clock offset at birth** (81 of 81 dates for every birth tested, once the Lahiri offset is removed). It never switches to the place's later clock.

### Reading section 1

- "Engine minus JHora" for antardasha starts compares the engine with JHora's own exact times, rebuilt from JHora's Moon with the same rule (JHora prints these dates without a time). The method is checked on the 5 births where JHora printed times: rebuilt and printed agree to within 19 s, far below the 1-hour tolerance.
- The difference is almost the same for every date of a birth, because it comes from one number: the Moon's position (0.1″ of Moon ≈ 1–3 min of dasha time). It never accumulates over the 120 years.
- **From 1900 (27 births):** largest 30.7 min (R03), typical 10.7 min. **Before 1900:** R26 (1853) 273.8 min ≈ 4.6 h, R29 (1895) 134.2 min ≈ 2.2 h, both inside the 12-hour tolerance (D-081).
- **Dates one day apart from JHora before the tolerance:** 53 of 2,349: **25 of 2,187 from 1900 (1.1 %, inside the 1–2 % estimated in D-079)** and 28 of 162 before 1900 (R26 19, R29 9). Each one is a start within ~30 min (R26: ~4.6 h) of midnight. All pass with the tolerance.

### Reading section 2 (D-097)

- (a) = engine UTC time + the fixed UTC offset at birth (as typed into JHora); (b) = engine UTC time shown in the place's IANA time zone **on that date** (summer time, later standard time). R27–R29 have no IANA zone in `births.json` (fixed historical clocks), so for (b) the place's zone today, Asia/Kolkata, is used; R26 likewise uses America/New_York. R19, R20 and R26 are extra rows (not asked for) because their offset also changes during life.
- With the engine's own times, (a) misses a few dates (R06, R20, R22, R26, R29). Those are exactly the "one day apart" dates of section 1 (the Lahiri offset), not a clock effect. With JHora's own times, **(a) matches 81/81 for every birth**.
- On the 20 dates where (a) and (b) give different days (R06 3, R16 2, R17 6, R22 1, R27 3, R28 1, R19 1, R20 3), JHora always prints (a)'s day.
- R18 (Sydney) and R29/R26 cannot tell the two clocks apart: no start falls in the hour where they would give a different day.
- **Conclusion for 0.3.7:** JHora uses the fixed offset at birth for every dasha date (e.g. +6:30 War Time for R06 for life; −4:00 US summer time for R16 even in winter). Whether Jathag does the same is the Project's decision (D-097).
